# スクショ整え

スクリーンショットを選ぶと、余白・背景・角丸・影を付けた画像になり、PNGで保存できるWebページです（100日100プロダクト Day066）。

- 画像（PNG・JPEG・WebP・20MBまで・1枚）を、選ぶ／ドラッグ＆ドロップ／貼り付け（PC）で読み込みます。「サンプルで試す」は、このページで描いた架空のアプリ画面です
- 比率（1:1 = 1080×1080、4:5 = 1080×1350、16:9 = 1920×1080、元の比率）・余白（小4%／中8%／大12%）・背景（単色6種・グラデーション4種）・角丸（なし／小／大）・影（なし／あり）をボタンで選ぶと、加工前と加工後を見比べながら結果が変わります
- 結果は、保存されるPNGと同じ1枚のcanvasです（プレビューと保存結果にずれがありません）
- 画像は端末のブラウザの中だけで処理し、保存もしません（通信はアクセス解析の閲覧数計測のみ）。AI・外部APIは使っていません

## 仕様の補足（実装で決めたこと）

- 出力の寸法（1080×1080・1080×1350・1920×1080）はこの道具の固定値です。各SNSの推奨サイズかどうかは調べていません。画面・投稿でもそう書きません
- 余白は出力の短辺×率です。「元の比率」は、出力＝画像＋余白×2、余白＝出力の短辺×率 を同時に満たすよう `余白 = 画像の短辺 × 率 ÷ (1 − 2×率)` で解いています（元の寸法が800×600・余白「中」なら余白57px、出力914×714）
- 拡大は2倍までです。それ以上小さい画像は、余白が大きくなります（「元の画像が小さいため、ぼやけることがあります」を出します）
- 左右・上下の余白の差が奇数pxになるときは、画像を1px小さくして完全に揃えます
- 影は、角丸にした画像を別のcanvasに作ってから影つきで貼ります。透明部分のあるPNGでも、透明な部分は背景色になり、黒く塗られません
- 長辺が4096pxを超える画像は、半分ずつ段階的に縮小して4096pxで扱います（表示します）
- 出力の色はページのライト・ダークに依存しません
- グラデーションは、出力の左上から右下への対角です（16:9では約29°。正方形で45°）
- 長辺が4096px、または1億画素を超える画像は、復号の前（ファイルの先頭の寸法）か復号のあとで止めるか縮小します。iPhoneではcanvasが約1677万画素までなので、途中のcanvasがそれを超えないようにしています（実機では未確認）
- iPhone・iPadでは、保存用のPNGを設定を変えた0.35秒後に先に作っておき、「PNGで保存」を押した操作の中では共有メニューを呼ぶだけにしています（実機では未確認）

## 限界・未確認

- **画像の中に写っている名前・メールアドレス・通知などは、この道具では隠せません**（画面に常設。隠すときは Day046「ここです」のモザイクを案内しています）
- iPhone・iPadの共有メニュー経由の保存、Androidの保存、貼り付け（paste）のスマホでの動作は、**実機では未確認**です（実在のUA文字列での分岐の検算と、Chromeでの模擬までです）
- WebP・向き（EXIF）の対応は、この環境のChromeで確認したものです。Safari・Firefoxなど他のブラウザは未確認です
- 出力はPNGのみです。元の画像より大きいファイルになることがあります
- 各SNSの画像の圧縮・推奨寸法は調べていません

## 検算
```
python source/make-fixtures.py <dir>          # 架空の検算用画像を作る
node source/run-checks.js <dir>               # 計算・判定・配色・静的検査
node source/e2e.js <dir> <out>                # 実ブラウザ(Chrome headless)で操作。出力PNGを <out> に書く
python source/check-output.py <out>           # 出力PNGをPillowで数値確認（S12）
node source/prep-images.js <dir>              # 投稿カードの元画像を用意
node source/shoot.js <dir> <out>              # 投稿カード用のスクリーンショット
```
